# Full System Health Status | 2026-11-13

## User behavior
An isolated system-status request in the local MellowCodex chat bypasses language-model inference and reads the same service_health.snapshot() used by the native Health & Recovery panel and Hub API /api/service-health. Common Hebrew, English, Russian, and several other status expressions are recognized. New chats and chats with active unrelated tasks use the same path. The report is persisted as a completed read-only turn with a small metadata evidence event; no history is deleted.

From the authenticated MellowCodex MCP connection, call the no-argument system_health_check tool for status or equivalent user intent in any language. The legacy service_health_status remains an alias. Both use the existing shared service-health endpoint and include a current authenticated MCP-to-Hub reachability observation in the response. Tool descriptions explicitly advertise multilingual full-system status. Connector discovery is not a guarantee that every ChatGPT client will automatically invoke this tool.

## Evidence semantics
The report covers Hub, MCP gateway, Guard, Guard OAuth gateway, SSH relay/network, Ollama, model loaded/unloaded state, OwnerBroker, recovery schedule, desktop, active tasks and separately observed external connector evidence. Each local service has its own checked_at, reason, status and evidence age. Connector proof expires after the existing 120-second TTL; older proof is stale, not a confirmed disconnect. An authenticated MCP call establishes a live MellowCodex MCP-to-Hub path. It does not independently prove SSH daemon authentication, forwarding, or every network address-family.

A failed inspection does not turn every service red. A deliberately unloaded model is not an outage. The command is read-only and does not load models, restart services, change permissions or reconnect OAuth.

## Status retry and independent public health route hardening (2026-11-13)
When the shared backend has a transient timeout or transport error, the status adapter performs at most one additional read-only check. It never restarts a service or bypasses owner/OAuth approval. If retries fail, it reports diagnostic failure/unverified service coverage, with older stored evidence marked stale rather than fresh. Public HTTP 502/503/504 and successful authenticated MCP are separate dimensions; operational local services and the MCP path may remain green while public /health diagnostic coverage is degraded. Mellow Guard.status() with omitted identifiers remains an independent Guard API limitation. New external ChatGPT tool discovery and UI click-through were not proven by local chat tests.

## 2026-11-13: Public health 503 event-loop deadlock correction
The full status chat HTTP route must offload synchronous Conversations.submit for isolated health intents. Otherwise, snapshot's public HTTP /health call can trigger Gateway's loopback callback into the very same busy Hub event loop, producing a self-induced 503. The /api/service-health endpoint was already offloaded; full chat status now is as well. Gateway also uses a bounded identity-validated lightweight Hub home response instead of the large OpenAPI document for readiness checks. When Hub is really down, 503 is still returned.
