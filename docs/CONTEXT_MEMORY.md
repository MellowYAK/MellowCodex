# Bounded context and durable working memory

The existing SQLite task/messages/actions/events remain authoritative. Context preparation never deletes history. Working state advances from committed event watermarks and uses revision checks; pending operations are evidence, never dispatch instructions. Existing recovery reconciles side effects.

hub/model_context.py builds disposable packets. Instructions/current user requirements, latest image and complete current tool exchanges are mandatory. Optional older groups are omitted under a working target; hard budget overflow produces context_budget_exceeded. Narrow synthesis paths share accounting without importing general task state. Counting is estimated, not an exact tokenizer. Runtime digest/template identity and postresponse Ollama prompt counts calibrate conservative margins. Image reserve remains uncertain.

The conversation memory dialog contains Context & Memory: policy, working target, measured input, output reserve, component totals, checkpoint and source pages. Settings are global, validated and persisted through the existing model-settings service. context_memory_status, context_memory_evidence, context_memory_pins, context_memory_pin use the same HTTP implementation. Project pins are explicit promotions; ordinary chat history is not cross-chat injected. Correct an anchor through existing supersession, then pin the corrected source.

Rollback: set context_management to legacy; no database downgrade or evidence deletion is required. shadow dispatches the legacy packet and measures the proposed packet without extra inference. Reset returns the configured default (shadow). Additive projection/pin/calibration tables are compatible with the prior path. Runtime source rollback uses the prepared Guard backup/receipt.

Deletion removes source-derived pin/projection records through triggers. Retrieval joins current source rows and checks hashes/supersession, so missing/edited sources are not returned as current. Token caches retain only content hashes and counts. Existing backups and task audit artifacts have their own retention; forgetting a current source does not erase historical backups.

Measured candidate results: four historical final-message packet replays reduced estimated selected input, with mandatory corrections retained. A real paired inference without historical tools measured 19,621 versus 8,205 input tokens (one pair, not whole-task savings). Wall time 11.297 versus 16.343 seconds: no latency improvement demonstrated. Isolated ordinary workflow read a disposable file exactly once and returned its expected code; two calls, 10,286 input and 48 output tokens.

Limitations: exact tokenizer parity not established; images use uncertain conservative reserve; full-task 30% target and statistical latency/resource improvements are not established by these small samples. Lexical retrieval and existing tool-discovery remain in use; semantic search was not justified or installed. Original evidence can be paged; bounded working state does not imply every stored fact is currently loaded. No compulsory summarizer/model call was added. Live deployment and UI/MCP readback evidence are recorded separately in release artifacts.
